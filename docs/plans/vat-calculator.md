| 착수 조건 | 위치 |

## 1. 한 줄 정의

**부가세 계산기는 공급가액과 합계금액(부가세 포함)을 서로 바꿔 계산하고, 간이과세자라면
업종별 부가가치율로 실제 납부할 부가세와 납부 면제 여부를 계산하는 도구다.**

## 2. 검색 의도와 사용자

| 항목 | 내용 |
|---|---|
| 주 검색 의도 | "부가세 계산기" · "부가세 포함 금액 계산" (공급가액을 넣으면 부가세와 합계가 얼마인가) |
| 보조 의도 | "부가세 역산" · "부가세 별도 계산" (합계 110만 원이면 공급가액이 얼마인가) · "간이과세자 부가세 계산" · "간이과세 납부면제" |
| 사용자 | 견적서·세금계산서를 쓰는 1인 사업자, 사업자등록한 프리랜서, 매입 금액을 확인하는 실무 담당자, 간이과세자 |
| 반복 상황 | 견적서 작성(부가세 별도/포함 표기), 카드 영수증의 공급가액 확인, 세금계산서 발행, 부가세 신고 전 납부액 예상 |
| 타겟 태그 | `small-business-owner` · `designer` · `developer` · `office-worker` |

프리랜서 3.3% 계산기의 limitations 에 "사업자등록한 일반과세자는 3.3% 가 아니라 세금계산서·부가세 10% 구조"라고
적어 두었다. 이 도구가 그 다음 단계 사용자를 받는다.

## 3. 산식

### 3.1 일반과세: 공급가액 → 합계 (정방향)

```
부가세   = 공급가액 × 10%          → 1원 미만 처리 (기본: 절사)
합계금액 = 공급가액 + 부가세
```

- 근거: 부가가치세법 제29조 (과세표준 = 공급가액), 제30조 (세율 100분의 10)
- 1원 미만 처리는 법이 정하지 않는다. 세금계산서 실무는 절사가 일반적이고 일부 POS 는 반올림한다.
  **기본값 절사, 옵션으로 반올림·올림**을 둔다. 이 처리 방식 선택 자체가 검색 상위 계산기에 대부분 없다.

### 3.2 일반과세: 합계 → 공급가액 (역산 · 차별화 핵심)

단순 계산 `합계 ÷ 1.1` 은 두 가지 이유로 틀릴 수 있다.

1. **부동소수점 오차.** `Math.floor(110000 / 1.1)` 은 `99999` 다 (`110000 / 1.1 = 99999.99999999999`).
   엔진은 원 단위 정수로만 계산하고 `합계 × 10 / 11` 을 정수 나눗셈으로 처리한다.
2. **절사 방향에 따라 답이 달라진다.** 합계를 고정하고 공급가액을 반올림하는 방식(카드 단말기·영수증)과,
   공급가액에서 10% 를 절사해 합계를 만드는 방식(세금계산서)은 다른 공급가액을 낸다.

엔진은 두 방식을 모두 계산해서 보여준다.

| 방식 | 계산 | 용도 |
|---|---|---|
| **A. 합계 고정 (기본)** | 공급가액 = round(합계 × 10 ÷ 11), 부가세 = 합계 − 공급가액 | 영수증·카드 매출, "부가세 포함 OO원" 견적 |
| **B. 정확 역산** | 공급가액 + 절사(공급가액 × 10%) = 합계 를 만족하는 공급가액 탐색 | 세금계산서를 이 합계로 맞춰 발행해야 할 때 |

방식 B 는 해가 없을 수 있다. 그때는 "이 합계를 정확히 만드는 공급가액은 없음"과 바로 아래·위 합계를 함께 보여준다.

**검산 예시 (계산기로 직접 확인)**

| 합계 | A. 합계 고정 | B. 정확 역산 (절사) | 비고 |
|---|---|---|---|
| 1,100,000 | 1,000,000 / 100,000 | 1,000,000 / 100,000 | 두 방식 일치 |
| 1,000,000 | 909,091 / 90,909 | 909,091 / 90,909 | 일치 |
| 99,999 | 90,908 / 9,091 | 90,909 / 9,090 | **공급가액 1원 차이** |
| 21 | 19 / 2 | 해 없음 (19 → 20, 20 → 22) | 소액 경계 |

```
99,999 × 10 ÷ 11 = 90,908.18 → 반올림 90,908, 부가세 9,091
90,909 × 10% = 9,090.9 → 절사 9,090, 90,909 + 9,090 = 99,999
```

이 1원 차이가 "세금계산서 공급가액과 카드 영수증 공급가액이 왜 다르냐"는 실제 질문의 답이다.
결과 카드에 두 방식이 다르면 차이와 이유를 한 줄로 표시한다.

### 3.3 품목별 계산 vs 합계 계산 (v1 포함 여부는 8장 결정)

견적서·세금계산서에 품목이 여러 줄이면 **품목별로 부가세를 절사해 더한 값**과
**공급가액 합계에 10% 를 곱해 절사한 값**이 다를 수 있다.

```
품목 3개, 각 공급가액 333원
품목별: 절사(33.3) × 3 = 33 × 3 = 99원
합계:   절사(999 × 10%) = 99원          → 이 경우는 같음
품목 3개, 각 공급가액 335원
품목별: 절사(33.5) × 3 = 33 × 3 = 99원
합계:   절사(1,005 × 10%) = 100원       → 1원 차이
```

품목 표 입력은 화면 복잡도를 올린다. v1 에서는 넣지 않고 FAQ·가이드에서 설명만 하는 안을 기본으로 둔다.

### 3.4 간이과세: 납부세액 (두 번째 탭)

```
납부세액     = 공급대가 × 업종별 부가가치율 × 10%
매입공제     = 세금계산서 등 수취 매입액(공급대가) × 0.5%
카드발행공제 = 신용카드·현금영수증 매출액 × 1.3%       (연 1,000만 원 한도 · 적용 기한 확인 필요)
차가감 납부세액 = 납부세액 − 매입공제 − 카드발행공제  → 0 미만이면 0 (간이과세자는 환급 없음)
                                                     → 10원 미만 절사
```

- 근거(대조 필요): 부가가치세법 제63조 (간이과세자의 과세표준과 세액) · 제46조 (신용카드 등의 사용에 따른 세액공제) ·
  시행령 제111조 (업종별 부가가치율) · 국고금 관리법 제47조 (끝수 계산)
- 간이과세자의 과세표준은 공급가액이 아니라 **공급대가(부가세 포함 금액)** 다. 화면 라벨에 명시한다.
- 공제 합계가 납부세액을 넘어도 환급되지 않는다는 점을 결과에 표시한다.

**업종별 부가가치율 (시행령 제111조 제2항, 2021. 7. 1. 이후 · 원문 대조 필요)**

| 업종 | 부가가치율 | 실효 부담률 (× 10%) |
|---|---|---|
| 소매업, 재생용 재료수집 및 판매업, 음식점업 | 15% | 1.5% |
| 제조업, 농업·임업 및 어업, 소화물 전문 운송업 | 20% | 2.0% |
| 숙박업 | 25% | 2.5% |
| 건설업, 운수 및 창고업(소화물 전문 운송업 제외), 정보통신업, 그 밖의 서비스업 | 30% | 3.0% |
| 금융 및 보험 관련 서비스업, 전문·과학 및 기술서비스업(인물사진·행사용 영상 촬영업 제외), 사업시설관리·사업지원 및 임대서비스업, 부동산 관련 서비스업, 부동산임대업 | 40% | 4.0% |

- 업종 선택은 이 표의 5개 그룹 셀렉트로 한다. 한국표준산업분류 세부 코드 검색은 하지 않는다.
- 겸업 사업자는 업종별로 나눠 계산해야 한다. v1 은 단일 업종만 계산하고 limitations 에 적는다.

### 3.5 간이과세: 납부 면제와 과세유형 경계

| 규칙 | 기준 | 화면 처리 |
|---|---|---|
| 납부의무 면제 | 해당 과세기간(1. 1.~12. 31.) 공급대가 합계 **4,800만 원 미만** (제69조) | 결과 최상단에 "납부 면제 대상 (신고는 해야 함)" 표시, 납부세액 0원 |
| 신규·휴업·폐업 | 공급대가를 12개월로 환산해 4,800만 원 미만 여부 판단 | "영업 개월 수" 입력을 두고 연 환산 금액을 함께 표시 |
| 간이과세 적용 범위 | 직전 연도 공급대가 **1억 400만 원 미만** 개인사업자 (법 제61조 · 시행령 제109조, 2024. 7. 1. 이후) | 입력 매출이 기준 이상이면 "다음 해 7월 1일부터 일반과세 전환 대상" 안내 |
| 부동산임대업·과세유흥장소 | 간이과세 기준 4,800만 원 미만 유지 | 해당 업종 선택 시 기준 금액을 바꿔 안내 |
| 세금계산서 발급 의무 | 직전 연도 공급대가 4,800만 원 이상 간이과세자 (영수증 발급 업종 제외) | 안내 문구만, 계산 영향 없음 |

- 면제는 **납부**만 면제다. 신고 의무는 남는다는 점을 결과와 FAQ 양쪽에 쓴다.
- 기준 금액은 개정 이력(4,800만 → 8,000만 → 1억 400만)이 있으므로 `policy.ts` 에 기간 테이블로 둔다.

### 3.6 일반과세 vs 간이과세 비교 (결과 하단 한 줄)

같은 매출·매입을 일반과세자로 계산하면 얼마인지 비교한다. "간이로 남는 게 유리한가"는 실제로 자주 나오는 질문이다.

```
일반과세 납부세액 = 매출 공급대가 × 10/110 − 매입 공급대가 × 10/110
```

**검산 예시 (연 매출 공급대가 6,000만 원 · 세금계산서 매입 공급대가 2,200만 원)**

| 업종 (부가가치율) | 간이 납부세액 | 매입공제 | 간이 차가감 | 일반과세라면 |
|---|---|---|---|---|
| 음식점업 (15%) | 900,000 | 110,000 | 790,000 | 3,454,540 |
| 정보통신업 (30%) | 1,800,000 | 110,000 | 1,690,000 | 3,454,540 |
| 전문서비스업 (40%) | 2,400,000 | 110,000 | 2,290,000 | 3,454,540 |

(카드발행공제 제외 · 일반과세 값은 10원 미만 절사 · 의제매입세액 등 다른 공제 미반영)

비교 결과에는 "과세유형은 선택이 아니라 직전 연도 매출과 업종으로 정해진다. 간이과세 포기 신고는 가능하다"를 함께 적는다.

- 결과 카드 primary 메트릭은 1개만 강조한다 (Clean SaaS 규칙).

### v1 범위 밖 (v2 후보)

- 품목 여러 줄 입력 (3.3 의 품목별 절사 차이 계산)
- 일반과세자 분기 신고 계산 (매출세액 − 매입세액 · 예정신고·확정신고 구분)
- 의제매입세액공제 (음식점업 면세 농산물 매입)
- 겸업 간이과세자의 업종별 안분
- 영세율·면세 거래

## 6. 테스트 항목

- 정방향: 1,000,000 → 부가세 100,000 · 합계 1,100,000
- 정방향 1원 미만 처리: 공급가액 12,345 → 절사 1,234 · 반올림 1,235 · 올림 1,235
- 역산 부동소수점: 합계 110,000 → 공급가액 100,000 (99,999 가 나오면 실패)
- 역산 방식 A·B 차이: 합계 99,999 → A 90,908 / B 90,909
- 역산 해 없음: 합계 21 → B 는 해 없음, 이웃 합계 20 · 22 제시
- 역산 무작위 검사: 1~10억 범위 표본에서 B 결과의 정방향 합계 = 입력 합계, A 는 공급가액 + 부가세 = 입력 합계
- 간이 납부세액: 3.6 표 세 행 (공식 산식으로 검증, 타 계산기 총액 하드코딩 금지)
- 간이 환급 없음: 매입공제가 납부세액보다 크면 차가감 0
- 납부 면제 경계: 공급대가 47,999,999 면제 · 48,000,000 납부
- 연 환산: 6개월 공급대가 2,500만 원 → 연 5,000만 원 환산 → 면제 아님
- 간이과세 기준 기간 경계: 2024-06-30 은 8,000만 원 · 2024-07-01 은 1억 400만 원
- 부동산임대업 선택 시 간이과세 기준 4,800만 원
- 10원 미만 절사 (국고금 관리법 제47조): 간이 차가감 납부세액
- 정책 상수: 부가가치율 표 5행 · 세율 10% · 매입공제 0.5%

## 8. 결정이 필요한 항목

1. **slug**: `vat-calculator` (제안, 로드맵 가칭) 또는 `korea-vat-calculator`
2. **간이과세를 같은 페이지 탭으로 둘지**: 제안은 탭. 검색 의도("간이과세자 부가세 계산")가 따로 있지만
   입력·산식이 달라 파생 페이지가 아니고, 한 페이지에서 일반과세와 비교하는 것이 차별화 포인트다.
3. **1원 미만 처리 옵션**: 절사 기본 + 반올림·올림 선택 (제안) 또는 절사 고정
4. **v1 범위**: 위 4장 범위로 확정할지, 품목 여러 줄 입력(3.3)을 v1 에 넣을지
5. **카드발행공제(1.3%) 포함 여부**: 적용 기한이 연장 입법에 의존한다. 원문 대조에서 2026년 적용이 확인되면 넣고,
   아니면 v1 에서 빼고 limitations 에 적는다.
