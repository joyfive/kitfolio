- 추가 개정: 페이지별 PC·모바일 크리틱, 블로그 개선 및 순차 구현 순서

- 목표: 필요한 도구를 빠르게 찾고, 입력한 뒤 결과를 가져가는 흐름을 화면의 최우선으로 만든다.

## 1. 검토 근거와 범위

운영 사이트의 데스크톱 홈, 390px 모바일 홈과 연봉 계산기 초기 화면을 공통 컴포넌트·CSS와 비교했다. 추가로 PC 1440×900에서 연봉 계산기, PDF 도구, JSON 포매터를 확인했다. 연봉 계산과 JSON 자동 정리는 예시 입력으로 결과가 표시되는 것까지 확인했다. PDF는 병합 탭의 파일 선택 전 상태를 검토했다. 실제 PDF 처리와 다운로드는 구현 후 검증에 포함한다.

`stageshow`의 초점, 시각적 위계, 정보 밀도, 모바일 재구성 원칙을 참고한다. 실제 서비스이므로 목업 전용 규칙인 콘텐츠를 회색 막대로 대체하기, 조작 영역을 크롭하기, 가짜 커서나 장식 애니메이션 넣기는 적용하지 않는다.

핵심 진단은 **소개와 반복 메타정보가 실제 작업보다 먼저 보인다**는 것이다. 색상 교체보다 탐색 → 입력 → 결과의 우선순위를 먼저 바로잡는다.

`design-taste-frontend`는 Kitfolio를 브라우저에서 바로 쓰는 소프트웨어로 보고, 구체적인 작업명과 실제 조작 화면을 중심으로 평가했다. 홈은 검색과 도구 진입 링크를 같은 첫 화면에 두고, 상세는 실제 작업 영역을 보여준다. PC에서 입력과 결과를 나란히 비교할 수 있는 구성은 연봉 계산기와 JSON 포매터의 강점이다.

## 2. 유지할 기반과 변경 범위

### 유지할 기반

- 청회색 배경과 파란 강조색, 기존 로고, 기본 서체.
- 설치·가입 없이 사용하는 제품 성격.
- 검색, 주제·작업 분류, 즐겨찾기, 한국어·영어 지원.
- 기존 도구 URL, 카테고리·작업 쿼리 파라미터, 로컬 즐겨찾기 데이터.
- 계산 로직, 입력 데이터의 브라우저 내 처리 방식, 구조화 데이터.

### 이번 리뉴얼에서 변경할 것

- 홈 상단의 높이와 탐색 요소 배치.
- 도구 카드의 정보량, 목록 구획, 텍스트 대비.
- 도구 상세의 소개·입력·결과·도움말 순서와 강조.
- 공통 컴포넌트의 반응형, 포커스, 터치 영역 및 상태 표현.
- 필요한 경우 대표 도구의 결과 미리보기.

새 도구 추가, 계산식 변경, URL 체계 변경, 광고 정책 변경은 별도 작업으로 분리한다. 리뉴얼을 이유로 정확성 안내나 적용 범위를 삭제하지 않는다.

## 4. 화면별 설계

### 4.1 홈: 검색과 도구 선택을 중심에 둔다

권장 정보 순서:

1. 브랜드 헤더.
2. 짧은 제목과 한 문장 소개.
3. 검색창과 보조 즐겨찾기 버튼.
4. 바로 열 수 있는 대표 작업 링크.
5. 주제 필터와 필요할 때 펼치는 작업 필터.
6. 결과 수·현재 선택 조건·조건 초기화.
7. 주제별 도구 목록.
8. 서비스 소개와 상세 처리 방침 안내.

실행 항목:

- [ ] 상단 배지와 소개에서 중복되는 ‘설치·가입 없이’ 표현을 정리한다.
- [ ] 홈 제목에 실제 작업을 넣는다. 문구 후보는 ‘PDF 합치기부터 연봉 계산까지’다. 소개에서 설치·가입 없이 쓸 수 있고 입력한 자료는 브라우저에서 처리된다는 점을 한 번 안내한다.
- [ ] 기본 홈의 검색창 바로 아래에 ‘PDF 합치기’, ‘사진 용량 줄이기’, ‘연봉 실수령액 계산’ 링크를 둔다. 각 링크는 실제 도구를 연다. 검색어나 필터가 활성화되면 결과를 먼저 표시한다.
- [ ] 긴 개인정보 처리 설명은 별도 안내로 옮기고 상단에는 짧은 요약과 상세 안내 링크를 둔다. 도구 입력과 제3자 네트워크 요청의 구분은 유지한다.
- [ ] 모바일 검색 placeholder를 짧게 작성한다. 예: `도구 검색: PDF 합치기`.
- [ ] placeholder와 별개로 검색 입력의 접근 가능한 이름을 제공한다.
- [ ] 즐겨찾기는 검색을 압도하지 않는 보조 버튼으로 배치한다. 시각적 크기를 줄여도 터치 영역은 확보한다.
- [ ] 모바일에서 주제 필터와 작업 필터를 같은 탐색 영역에 둔다. 두 개의 별도 고정 바는 만들지 않는다.
- [ ] 작업 필터는 ‘작업으로 좁히기’로 접고, 선택 시 현재 조건을 표시한다. 선택한 주제에 해당하는 작업만 제공하는 기존 규칙은 유지한다.
- [ ] 기본 전체 보기에는 주제별 제목을 표시하고, 특정 주제나 검색 결과에서는 불필요한 구획을 줄인다.
- [ ] 하단 서비스 소개는 카드 세 장을 일반 제목과 본문으로 바꿔 도구 목록과 구분한다.
- [ ] 검색 결과 없음과 즐겨찾기 없음의 문구를 구분하고 각각 검색·필터 해제, 즐겨찾기 추가 안내를 제공한다.
- [ ] 스크롤 고정 요소가 콘텐츠와 포커스를 가리지 않는지 확인한다.

검색·필터 활성 상태에서는 결과를 가까이 보여준다. ‘인기 도구’는 근거 데이터 없이 만들지 않는다. 최근 사용 목록은 별도 기능이므로 이번 필수 범위에 포함하지 않는다.

### 4.2 도구 카드: 읽는 순서를 단순화한다

기본 구성은 **도구 식별 요소 → 현재 언어 도구명 → 할 수 있는 일 한 문장 → 진입 표시**로 한다.

- [ ] 홈 카드의 다른 언어 이름 병기를 제거한다. 언어 전환과 검색용 한·영 이름은 유지한다.
- [ ] 설명은 사용자가 얻는 결과를 중심으로 작성한다. 중요한 제한을 말줄임으로 숨기지 않는다.
- [ ] 주제별 목록에서는 반복 주제 태그를 제거한다. 검색처럼 맥락이 섞인 목록에서만 필요한 분류를 보조 표시한다.
- [ ] 작업 태그는 기본 카드에서 제거하고 필터에서 제공한다.
- [ ] 작업을 잘 나타내는 기호는 작은 라벨로 남긴다. 타일 배경의 강조를 낮추고, 기호와 제목을 바로 연결한다. 기호 선정 규칙은 10절을 따른다.
- [ ] 즐겨찾기는 카드 링크와 독립된 조작 요소로 구현한다. 링크 내부에 버튼을 중첩하는 현재 구조를 정리한다.
- [ ] 데스크톱 키보드 포커스에서도 진입 표시와 즐겨찾기가 보이도록 한다.
- [ ] 모바일은 데스크톱 카드를 단순히 한 열로 쌓기보다 식별 요소와 본문을 나란히 둔 간결한 구성도 비교한다.
- [ ] 제목 길이와 설명 길이가 다른 카드들을 한 화면에서 비교해 정렬을 확인한다.

### 4.3 도구 상세: 입력과 결과를 앞에 둔다

권장 정보 순서:

1. 홈/주제 복귀 경로와 적용 범위.
2. 현재 언어 제목과 한 문장 설명.
3. 주요 입력과 결과 영역.
4. 결과 해석에 필요한 한계·주의사항.
5. 자세한 사용법, 예시, 근거 자료, FAQ.
6. 관련 도구.

실행 항목:

- [ ] 공통 `PageHead`의 긴 설명을 짧은 소개와 상세 설명으로 분리한다. 기존 `description`을 무작정 덮어써 메타데이터·다른 영역까지 바꾸지 않는다.
- [ ] 한국어 화면의 영문 부제는 기본 상단에서 제거한다. 영어 화면은 영어 제목을 사용한다.
- [ ] 일반적인 3단계 안내는 입력 아래 도움말로 옮긴다. 오류를 예방하는 필수 안내는 해당 필드 가까이에 남긴다.
- [ ] 데스크톱은 입력과 결과를 나란히, 모바일은 주요 입력 다음에 결과가 이어지는 구성을 우선 검토한다.
- [ ] 추가 설정은 의미 있는 기본값이 있는 경우 접을 수 있도록 검토한다. 현재 적용 값 요약을 보여주고 필수 항목을 숨기지 않는다.
- [ ] 결과의 핵심 숫자 또는 산출물 하나에 가장 강한 강조를 준다. 상세 수치·표는 보조 위계로 정리한다.
- [ ] 복사·다운로드를 결과 가까이에 배치하고 성공 피드백을 제공한다.
- [ ] 초기·처리 중·성공·오류·입력 변경 후 결과 상태를 구분한다. 실제 계산하지 않은 결과를 초기 화면의 결과처럼 보여주지 않는다.
- [ ] 계산기에서는 적용 연도·지역과 예상치 여부를 결과 가까이 유지한다.

### 4.4 대표 도구 미리보기: 선택 작업

필수 레이아웃 변경 후 필요성이 확인될 때만 진행한다.

- 후보: 이미지 압축 전후 용량, 생성된 QR 코드, 정리된 JSON.
- 실제 도구의 결과 형태를 사용하고 예시 데이터임을 명시한다.
- 전체 창을 작게 축소한 이미지 대신 결과를 읽을 수 있는 부분만 보여준다.
- 모바일에서 별도 큰 히어로로 검색을 밀어내지 않는다.
- 정적 이미지 또는 정적 UI로 먼저 검토한다. 애니메이션은 효용이 있을 때만 추가하며 reduced motion을 지원한다.

## 8. 완료 판단

리뉴얼의 완료 기준은 새로운 장식의 양이 아니다. **사용자가 도구를 찾고, 입력하고, 결과를 가져가는 순서가 화면에서도 가장 먼저 읽히는지**로 판단한다.

필수 완료 범위는 검색창 수정, 실제 작업을 담은 홈 제목과 대표 작업 링크, 목록 구획과 카드 단순화, 대표 상세 3종의 입력·결과 개선, 접근성·반응형 검증이다. 결과 미리보기는 선택 사항이며 필수 작업의 완료를 지연시키지 않는다.

| JSON 포매터 `/json-formatter` | 좌우 편집기가 입력과 결과의 관계를 잘 보여준다. 자동으로 정리되는데 파란 ‘포맷’ 버튼이 필수 단계처럼 보인다. 자동 정리를 표시하고 결과 옆 복사를 강조한다. | 들여쓰기·포맷·압축 라벨이 글자 단위로 줄바꿈된다. 결과 코드 영역은 초기 예시 상태에서 약 28px 높이로 눌려 내용이 보이지 않는다. 도구 모음을 줄을 나눠 배치하고, 입력 아래에 읽을 수 있는 높이의 결과 영역과 복사 버튼을 둔다. 안내 문구는 ‘오른쪽’ 대신 화면 배치에 공통으로 맞는 표현을 쓴다. |

| 블로그 글 상세 `/blog/[slug]` | PDF 글은 읽기 좋은 본문 폭을 갖췄다. 다만 약 406px 높이의 커버 때문에 첫 본문 소제목이 화면 끝에 걸리고, 도구 링크는 글 아래 ‘바로 써보기’에 모여 있다. 커버를 줄이거나 설명에 직접 도움 되는 도식으로 바꾸고 요약 직후 관련 도구 링크를 둔다. | PDF 글은 큰 커버와 첫 문단을 지나 약 775px에서 첫 본문 소제목이 보인다. 제목·요약·대표 도구 링크를 먼저 배치하고 커버를 줄이거나 관련 설명 가까이 옮긴다. 본문과 링크가 320px 및 글자 확대에서도 겹치지 않는지 확인한다. |

### 9.1 블로그 작업 항목

- [ ] [블로그 목록](https://kitfolio.app/blog)에서 주제를 단순 태그로 표시할지 실제 탐색 링크로 만들지 결정한다. 현재 글 수에서는 날짜·제목·요약·태그를 모두 같은 무게로 반복하기보다, 작업 주제와 제목부터 빠르게 읽히는 구성을 우선한다.
- [ ] 카드 제목은 작업이나 문제를 먼저 말하고, 요약은 글에서 가져갈 내용 한 가지를 덧붙인다. PC 3열과 모바일 목록형은 같은 순서로 정보를 제공한다.
- [ ] 첫 화면에 필요한 썸네일의 로딩을 확인한다. PC 첫 캡처에서 커버가 잠깐 비어 있었지만 후속 캡처에서는 정상 표시됐다. 느린 연결에서 재현 여부와 이미지 로딩 정책을 확인한 뒤 수정한다.
- [ ] [PDF 글](https://kitfolio.app/blog/pdf-tasks-in-browser) 요약 가까이에 관련 도구 링크를 배치한다. PC·모바일에서 해당 작업으로 진입하는지 확인하고 기존 하단 링크와의 반복을 정리한다.
- [ ] `BlogList.tsx`, `BlogArticle.tsx`, 관련 CSS와 글 앞부분의 Markdown을 함께 점검한다. PDF 글을 기준으로 적용한 뒤 JSON 또는 연봉 글에서 제목 길이와 커버가 달라져도 동작하는지 확인한다.

### 9.2 프롬프트 페이지

최신 `main`에 프롬프트 목록과 상세 라우트가 추가됐다. `content/prompts`에는 작성 템플릿만 있고 운영 `/prompts`는 404를 표시한다. 공개 글이 있는 언어에서 목록과 메뉴가 열리도록 구현돼 있다. 임시 로컬 복제본에 한국어 검토용 글 두 편을 넣어 PC 1440×900과 모바일 390×844의 목록·상세를 확인했다. PC에서 복사 클릭 후 ‘복사됨’ 표시를 확인했다. 모바일은 버튼 크기와 배치를 확인했으며 실기기 터치와 클립보드 실패는 구현 후 검증한다.

| 페이지 | PC 개선 | 모바일 개선 | 완료 기준 |
| --- | --- | --- | --- |
| 프롬프트 목록 `/prompts` | 약 210px 높이의 제목 썸네일 아래 같은 제목과 공통 배지가 반복된다. 제목을 카드당 한 번만 표시한다. 작업 제목과 어떤 결과를 얻는지 알려주는 설명을 먼저 배치한다. | 첫 카드가 약 369px를 차지한다. 두 번째 제목은 보이지만 설명은 화면 아래에 걸린다. 제목·짧은 설명 중심으로 줄여 첫 두 항목의 용도를 비교할 수 있게 한다. | 1440×900과 390×844에서 여러 프롬프트의 용도를 제목과 설명으로 비교할 수 있다. 390px에서 최소 두 제목이 첫 화면에 보이는 것을 목표로 한다. |
| 프롬프트 상세 `/prompts/[slug]` | 본문 폭은 읽기 좋다. 요약과 ‘이럴 때 쓰세요’ 안내를 지난 뒤에야 복사 행동이 보인다. 요약 다음에 대표 프롬프트와 ‘프롬프트 복사’를 배치한다. 게시일·작성자와 적용 가이드는 읽는 순서를 정리하고, 메뉴 경로 확인일은 관련 안내 가까이에 둔다. | 복사 버튼은 약 43×28px이고, 코드 블록 오른쪽 76px을 비워 문장이 일찍 줄바꿈된다. 버튼을 블록 헤더로 옮겨 44×44px 이상을 목표로 하고 본문 전체 너비를 확보한다. 긴 한글·영문과 치환 자리 표시가 320px에서도 잘리지 않도록 한다. | 짧은 소개 뒤 대표 프롬프트와 복사를 찾을 수 있다. 키보드와 터치로 원문을 복사하고, 성공과 실패를 화면 및 보조 기술에 알린다. |

- [ ] 새로고침 직후 복사 버튼이 붙기 전에는 긴 문장이 블록 안에서 가로로 잘려 보였다. 줄바꿈 스타일은 첫 렌더부터 적용하고 복사 준비 과정에서 블록이 크게 재배치되지 않게 한다.
- [ ] 목록·상세의 공통 스타일 수정 후 블로그 화면도 함께 확인한다.
- [ ] 코드 예시가 여러 개라면 붙여넣을 대표 프롬프트와 적용 예시를 구분한다. 본문 안의 예시 코드까지 전부 같은 복사 행동으로 강조할지 검토한다.
- [ ] 공개 전에는 개발용 글로 긴 제목, 긴 프롬프트, 복사 권한 실패, 언어별 노출 조건을 확인한다. 공개 글이 생기면 운영 PC·모바일도 재검증한다.

### 9.3 코드 개선 순서

1. **홈 P0와 공통 상세 헤더**부터 수정한다. 모바일 검색창이 눌리는 문제를 해결하고, 상세 소개를 짧게 줄여 입력이 위로 오게 한다.
2. **JSON 포매터**의 모바일 결과 영역과 도구 모음을 수정한다. PC 좌우 배치, 자동 정리, 오류 표시, 복사까지 확인한다.
3. **연봉 계산기 → PDF 도구** 순으로 입력 전후 화면을 정리한다. 연봉은 예시 입력 후 결과 비교, PDF는 샘플 파일 두 개로 병합과 다운로드까지 확인한다.
4. **홈 탐색과 카드**에 새 제목, 대표 작업 링크, 주제별 목록을 적용한다. 검색 및 필터 상태와 기존 즐겨찾기 동작을 확인한다.
5. **블로그 목록 → 글 상세** 순으로 개선한다. 목록에서 글을 찾고, 글에서 관련 도구를 여는 흐름을 PC와 모바일에서 확인한다.
6. **프롬프트 목록 → 상세** 순으로 개선한다. 블로그와 공유하는 스타일을 확인한 뒤, 작업을 고르고 복사하는 흐름을 PC와 모바일에서 검증한다.

각 작업은 해당 페이지의 PC·모바일 전후 화면과 주요 조작을 확인한 뒤 다음 단계로 넘어간다. 공통 헤더나 CSS를 바꾼 경우 이미 검토한 대표 화면에서도 회귀를 확인한다.

## 10. 브랜드 개선 계획

**디자인 방향은 ‘라벨이 붙은 작은 업무 도구함’이다.** Kitfolio를 처음 열면 어떤 작업을 할 수 있는지 빠르게 구별하고, 도구나 글을 열면 얻을 결과와 다음 행동이 눈에 들어오게 한다. 기존 청회색·파란색·2×2 로고 위에 작업 기호와 결과 표현을 더해 홈, 도구, 블로그, 프롬프트가 같은 제품으로 읽히게 한다.

### 공통 시각 규칙

- **기호는 작업의 라벨로 쓴다.** `¶`(글자 수), `₩`(급여), `px`(CSS 단위), `{ }`(JSON), `PDF`처럼 실제 작업에서 쓰는 표기를 도구 이름 옆에 둔다. 첫 적용에서 이 다섯 가지로 크기, 정렬, 글자 굵기를 맞춘다. 여러 도구가 같은 기호를 쓰면 제목으로 구분하고, 한 기호에 뜻을 억지로 부여하지 않는다. 보조 기술에는 도구 이름을 읽히게 한다.
- **파란색은 행동과 결과의 우선순위를 보여준다.** 시작 전에는 검색·파일 선택처럼 지금 해야 할 행동, 처리 후에는 월 실수령액·다운로드·복사처럼 결과를 확인하거나 가져가는 행동을 가장 강하게 표시한다. 필터 선택, 키보드 포커스, 오류는 각각 상태를 알아볼 수 있게 표현한다.
- **예시는 실제 작업에서 가져온다.** 이미지 압축 전후 용량, PDF 페이지 순서, 정리된 JSON, 프롬프트 원문처럼 작업을 설명하는 내용이 화면의 중심이 되게 한다. 예시에는 가상 데이터를 사용하고 ‘예시’임을 표시한다.
- **문구는 작업과 결과를 직접 말한다.** 홈 링크는 ‘열기’보다 ‘PDF 합치기’처럼 읽고 바로 행동할 수 있게 쓴다. 결과 영역은 ‘월 실수령액’, ‘PDF 다운로드’, ‘프롬프트 복사’처럼 가져갈 것을 이름으로 표시한다.

### 화면별 첫 적용 범위

| 화면 | 적용할 브랜드 단서 | PC·모바일에서 확인할 기준 |
| --- | --- | --- |
| 홈 | 검색 아래 대표 작업에 작업명과 라벨을 짝지어 배치한다. PC에서는 로고의 2×2 구조를 참고한 대표 작업 묶음을 한 곳에서 시험한다. 네 칸이 필요한 시안에는 기존 세 작업에 ‘JSON 정리’를 더한다. | PC에서는 로고와 대표 작업 라벨의 형태가 자연스럽게 이어진다. 390px에서는 한 줄 목록이나 짧은 링크 묶음을 비교하고, 검색과 첫 도구가 기존 계획의 첫 화면 목표를 충족하는 구성을 선택한다. |
| 도구 상세 | 연봉은 월 실수령액, PDF는 파일 선택과 완성 파일, JSON은 정리된 코드와 복사를 각각 중심에 둔다. 공통 라벨·색·문구 규칙을 세 화면에 적용한다. | 같은 색의 역할이 화면마다 일관되고, 사용 전후에 시선이 향하는 곳이 작업 단계에 맞게 바뀐다. |
| 블로그 | PDF 글 한 편에서 추상 표지와 실제 작업을 담은 예시를 비교한다. 후보는 페이지 썸네일을 재배열해 하나의 PDF가 되는 모습이다. 목록에 표시할 관련 작업명도 글 제목 가까이에 둔다. | PC와 390px에서 표지나 목록을 훑었을 때 어떤 작업을 다루는지 알 수 있고, 대표 글의 첫 본문과 도구 링크가 큰 이미지 때문에 밀리지 않는다. |
| 프롬프트 | 목록은 ‘회의 메모 → 결정 사항·담당자·기한’처럼 작업명과 결과를 보여준다. 상세는 실제 원문과 ‘프롬프트 복사’를 한 덩어리로 두고, 적용 위치를 가까이 안내한다. | PC와 390px에서 두 프롬프트의 용도를 비교할 수 있고, 상세에서는 원문과 복사 행동이 함께 읽힌다. |

### 비교와 적용 순서

1. 기존 기능 수정 순서는 9.3절을 따른다. 홈 대표 작업 묶음, 연봉 결과, PDF 글 표지, 프롬프트 상세를 브랜드 규칙의 첫 적용 화면으로 삼는다.
2. 1440×900과 390×844에서 기존 화면과 변경안을 비교한다. 로고와 페이지명을 가린 캡처에서도 작업 기호·핵심 결과·문구 처리가 서로 같은 제품의 원칙으로 보이는지 검토한다. 각 화면에서 어떤 일을 할 수 있는지와 무엇을 먼저 눌러야 하는지도 확인한다.
3. 확인된 규칙을 나머지 화면에 확장한다. 2×2 배치와 이미지 미리보기는 모바일 탐색 속도와 가독성을 개선하거나 유지하는 경우 채택한다.

| PDF·JSON | 390px과 1440px에서 두 PDF의 순서를 바꿔 병합했다. 다운로드 파일을 읽어 결과가 바뀐 페이지 순서와 일치함을 확인했다. 같은 두 폭에서 JSON 입력 즉시 결과 갱신, 클립보드 원문, 잘못된 JSON 오류와 복사 비활성을 확인했다. |
| 블로그·프롬프트 | 모바일 목록에서 여러 글을 빠르게 훑을 수 있게 했고, PDF 글은 파일 합치기 예시와 도구 링크를 앞에 배치했다. 터치로 블로그 목록에서 PDF 글을 거쳐 도구까지 열었다. 프롬프트는 임시 개발용 한·영 글에서 대표 원문, 키보드·클릭 복사, 원문 일치와 실패 안내를 확인했다. 공개 콘텐츠가 생기면 같은 검증을 운영에서도 진행한다. |
| 화면 크기 | 한국어·영어 각 35개 도구의 초기 화면에서 320, 390, 768, 1280, 1440px를 확인했다. Slack 타임스탬프 예제와 Tailwind 팔레트에서 발견한 가로 넘침을 수정하고 재검사했다. 대표 화면은 1440px 창의 200% 확대에 해당하는 720px 너비에서도 별도로 확인했다. |
| 접근성 | 390px의 대표 8개 화면에서 첫 화면에 표시되는 글자와 배경의 대비를 계산했다. 확인된 저대비 레이블을 보강하고 동일 범위에서 4.5:1 기준 미달이 없음을 재확인했다. 검색·금액 입력·PDF 선택 테두리와 포커스 색을 강화했다. 검색, 즐겨찾기, 대표 작업, JSON 결과 복사, 프롬프트 복사 버튼의 주요 모바일 조작 높이는 44px 이상이다. |
| 브랜드 비교 | 홈, 대표 상세 3종, 블로그 목록·PDF 글, 프롬프트 목록·상세의 전후를 1440×900과 390×844에서 캡처했다. 로고와 제목을 가렸을 때 작업 라벨, 파란 주 행동, 파일명·코드처럼 실제 작업을 보여주는 요소가 이전보다 명확했다. 적용한 2×2 묶음은 유지하고, 별도 결과 미리보기와 애니메이션은 이번 시안에서 생략했다. |
| 자동 검증 | 단위·회귀 테스트 618개와 색인 대상 도구 28개의 콘텐츠 검증을 통과했다. 프로덕션 빌드에서 정적 페이지 188개를 생성했다. |
