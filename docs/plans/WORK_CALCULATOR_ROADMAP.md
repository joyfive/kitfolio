# 업무·세금 계산기 로드맵 (2026-10-01 수립)

## 0. 목적

검색 의도가 분명한 업무·세금 계산기를 **하나씩 딥다이브해서** 기획하고 개발한다.
"세금 계산기" 같은 포괄 페이지 하나를 만들지 않는다. 계산식과 검색 의도가 도구마다
다르기 때문에 **도구 1개 = 검색 의도 1개 = 계산 엔진 1개** 로 만든다.

## 1. 진행 원칙

1. **한 번에 하나씩.** 앞 도구가 배포되고 품질 게이트를 통과한 뒤 다음 도구 기획에 들어간다.
2. **기획 문서 먼저.** 도구마다 `docs/plans/<slug>.md` 기획서를 쓰고 합의한 뒤 `/build-tool` 로 구현한다.
   기획서에는 산식 · 법적 근거 · 엣지케이스 · 입력/출력 · 차별화 포인트 · 콘텐츠 골격 · 테스트 항목을 담는다.
3. **정책 데이터는 기간으로 관리.** 세율·한도는 연도가 아니라 `effectiveFrom/To` 기간 테이블에 둔다
   (`app/lib/salary/insurance.ts` 패턴). 출처·검증일은 도구별 `sources.ts` 가 단일 출처다
   (`app/lib/severance/sources.ts` 패턴).
4. **출처는 1차 자료만.** 국세청 · 고용노동부 · 국가법령정보센터. 개인 블로그·타사 계산기 금지.
5. **테스트는 공식 산식으로.** 타 계산기의 결과 총액을 하드코딩 비교하지 않는다.
   요율 상수와 기간 경계, 절사·최저한 같은 규칙을 따로 검사한다.
6. **`indexable: false` 로 시작.** ko/en 모두 `npm run validate:content` 를 통과하면 승격한다.
7. **얇은 계산기 금지.** 곱셈 한 번으로 끝나는 페이지는 AdSense 저품질 반려 사유와 같다.
   역산 · 규칙 예외 · 비교처럼 **검색 상위 계산기에 없는 깊이**가 기획서에 있어야 착수한다.

## 2. 대상 도구와 순서

25점 평가는 `docs/ai/TOOL_SELECTION.md` 기준. 검색 수요 점수는 정성 추정이며
기획 단계에서 네이버 키워드도구 · Search Console 로 확인한다.

| 순서 | 도구 | 가칭 slug | 점수 | 타겟 | 상태 |
|---|---|---|---|---|---|
| 1 | 프리랜서 3.3% 계산기 (사업소득 · 기타소득 8.8%) | `freelancer-tax-calculator` | 24 | designer · developer · pm · office-worker | ✅ v1 배포 대기 · indexable 승격 전 ([기획서](./freelancer-tax-calculator.md)) |
| 2 | 연차 계산기 | `annual-leave-calculator` | 24 | office-worker · pm · job-seeker | ⬜ |
| 3 | 부가세 계산기 (일반 · 간이과세) | `vat-calculator` | 23 | small-business-owner | ⬜ 조건부 |
| 4 | 실업급여 계산기 | `unemployment-benefit-calculator` | 21 | office-worker · job-seeker | ⬜ |
| 5 | 종합소득세 계산기 | `income-tax-calculator` | 20 | small-business-owner · 프리랜서 | ⏸ 보류 |

**범례:** ⬜ 대기 · 🚧 진행 중 · ✅ 배포 · ⏸ 보류 · ❌ 제외

### 도구별 메모

**1. 프리랜서 3.3% 계산기**
- 지급액과 실수령액을 서로 역산한다. 사업소득 3.3% 와 기타소득 8.8% 를 비교한다.
- 연봉 실수령액 · 퇴직금 계산기와 Related Tools 로 묶는다.

**2. 연차 계산기**
- 입사일 기준과 회계연도 기준의 발생 연차, 1년 미만 월 단위 연차, 3년차 이후 가산 연차를 계산한다.
- 근로기준법 제60조 규칙만으로 계산한다. 공휴일 데이터(`app/lib/holidays.ts`)를 재사용할 수 있다.
- 퇴직금 · 유연근무 계산기와 같은 직장인 묶음이다.

**3. 부가세 계산기 (조건부)**
- 검색 수요는 가장 크지만 공급가액 × 10% 만으로는 만들지 않는다.
- 착수 조건: 합계금액에서 공급가액 역산, 원 단위 절사 차이, 간이과세 업종별 부가가치율과
  납부 면제 기준까지 기획서에 담길 것.

**4. 실업급여 계산기**
- 구직급여일액 상한 · 하한(최저임금 연동)이 해마다 바뀌므로 기간 테이블이 필수다.
- 소정급여일수(나이 · 가입기간)를 표로 관리한다.

**5. 종합소득세 계산기 (보류)**
- 공제 항목이 많아 정확도 위험이 크고 하루 안에 구현하기 어렵다.
- 홈택스 모의계산과 경쟁해야 한다. 1번 도구의 "5월 신고 때 환급 또는 추가 납부" 안내로 수요를 먼저 확인한다.

### 제외

| 후보 | 사유 |
|---|---|
| 연말정산 계산기 | 공제 구조가 복잡해 하루 구현 기준을 넘는다. 국세청 공식 도구가 있다. |
| 양도세 · 취득세 계산기 | 검색량은 크지만 부동산 도메인이라 "지식 노동자용 작은 도구"와 맞지 않는다. |

## 3. 도구마다 반복하는 절차

1. 기획서 작성 (`docs/plans/<slug>.md`) · 검색 키워드 확인 · 법령·고시 원문 대조
2. 합의 후 `/build-tool` 로 구현: 정책 데이터 · 계산 엔진 · 테스트 → 컴포넌트 → 레지스트리 ko/en → 라우트 · OG
3. `npm test` · `npm run validate:content` 통과
4. CLAUDE.md "구현된 기능 목록"과 이 문서 상태 갱신
5. 배포 후 Search Console 노출을 보고 `indexable: true` 승격
